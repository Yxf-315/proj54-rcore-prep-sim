## 3. 旁白全文（可直接照读，约 520 字）

> （镜 1）这是 rCore 配套预习模拟器，用 Rust 写的一个命令行小程序。它只做一件事：把 Sv39 地址翻译讲清楚。
>
> （镜 2）初学者进 Lab3 之前通常有三道坎：页表是黑箱，PTE 里有什么不知道；缺页难定位，写错一个位域就是三重故障；还有 Rust 的所有权，知道 move 会失效，却不知道它正是内核防双重释放的机制。
>
> （镜 3）我们没有再写一个内核，而是在用户态复刻了 rCore 的帧分配器和三级页表。零第三方依赖，一条命令启动。
>
> （镜 4）先看帧分配。分配三帧，水位线从 1 走到 4；释放中间一帧，帧进入回收栈；再分配时优先复用刚释放的 PPN。这就是 rCore 的栈式分配器。
>
> （镜 5）FrameTracker 离开作用域会自动归还物理帧。它没有实现 Clone，所以同一帧不可能有两个主人——双重释放写不出来。
>
> （镜 6）核心是页表。建立一条映射，然后 walk：L2、L1、L0 三级依次展开，每一级的页表项地址、原始值、权限位都打印出来。
>
> （镜 7）手工验证一下：虚拟地址 0x1000，右移 12 位等于 1，所以 VPN[0] 是 1，VPN[1] 和 VPN[2] 都是 0，最终翻译到物理地址 0x8000_5000。
>
> （镜 8）再做两次访存：只读页写访问，权限异常定位在 L0；从未映射的地址读，缺页定位在 L2。内核处理缺页时，最需要的就是“停在第几级”这个信息。
>
> （镜 9）配套的 8 个测试用例，对应 8 个实验观察点，一条命令自动判定，也接入了 CI。
>
> （镜 10）指导书、测例、试用数据构成教学闭环。下一步我们会做 Lab4 的任务切换和 COW。谢谢观看。

## 4. 录制执行步骤

```powershell
cd rcore-memlab
cargo build                      # 提前编译，录制时不再编译
.\target\debug\memlab.exe        # 启动交互模式
```

按分镜顺序逐条粘贴：

```text
alloc 3
frames
demo raii
map 0x1000 auto rw
walk 0x1000
map 0x2000 auto r
fault 0x2000 w
fault 0x9000
```

最后退出终端，运行：

```powershell
.\target\debug\memlab.exe --check cases
```

## 5. 剪辑与导出

- 片头 0.5 秒淡入，片尾 1 秒淡出；
- 全程加字幕（剪映“识别字幕”后再校对专有名词：Sv39、VPN、PTE、FrameTracker）；
- 关键行用方框高亮（L0 / L2 / 翻译结果），不要用花哨转场；
- 导出：H.264、1080p、码率 4–6 Mbps，目标 ≤ 100 MB；
- 命名 `06-demo.mp4`，与提交目录一致。
