## 2. 背景知识速查

### 2.1 物理内存与页帧

rCore 在 QEMU `virt` 平台上从 `0x8020_0000` 附近开始管理物理内存，页大小 4 KiB。
物理地址除以 4096 就是页帧号（PPN）。本实验台为了演示方便，把可用内存设为
`0x8000_0000 .. 0x8400_0000`（64 MiB = 16384 帧），根页表占用 `0x8000_0000` 这一帧。

### 2.2 Sv39 地址拆分

39 位虚拟地址（本实验台只支持低半区，即 `< 2^38`）被拆成：

```
 38      30 29      21 20      12 11        0
+----------+----------+----------+-----------+
|  VPN[2]  |  VPN[1]  |  VPN[0]  |  offset   |
|  9 bit   |  9 bit   |  9 bit   |  12 bit   |
+----------+----------+----------+-----------+
```

每一级页表 512 项、每项 8 字节，所以第 `level` 级页表项地址为：

```
pte_addr = table_pa + index(level) * 8
index(level) = (va >> (12 + 9*level)) & 0x1ff
```

### 2.3 页表项（PTE）低 8 位

| 位 | 名称 | 含义 |
| --- | --- | --- |
| 0 | V | 有效 |
| 1 | R | 可读 |
| 2 | W | 可写 |
| 3 | X | 可执行 |
| 4 | U | 用户态可访问 |
| 6 | A | 已被访问（硬件置位） |
| 7 | D | 已被写过（脏页） |

`R/W/X` 全为 0 的项是**非叶子项**，指向下一级页表；只要有一个为 1 就是叶子项。

### 2.4 命令速查

```
lab lab2        # 物理帧分配器实验脚本
lab lab3        # Sv39 页表实验脚本
alloc 3         # 分配 3 帧
free 0x8_0002   # 释放指定 PPN
map 0x1000 auto rw    # 建立映射（auto 自动分配物理帧）
walk 0x1000     # 逐级遍历并翻译
fault 0x1000 w  # 模拟写访问
status / frames # 总览 / 分配器统计
demo raii       # 所有权演示
```

## 6. 实验四（挑战）：扩展实验台

从下面任选一项，在 `src/` 中实现并补充测试：

### A. `unmap` 时回收空页表

当前 `PageTable::unmap` 只清叶子项，中间级页表会一直占着帧。实现：

- 拆除叶子后，若某一级页表的 512 项全为空，则释放该页表帧并把上级 PTE 清零；
- 增加命令 `unmap --prune <va>` 或在 `unmap` 中默认开启；
- 验收：`map` 一页后 `unmap`，分配器持有帧数回到映射前。

### B. 大页映射（2 MiB）

- 实现 `map_huge <va> <pa>`，在 L1 直接写叶子项（`R/W/X` 置位、不再指向 L0）；
- 让 `walk` 与 `translate` 能正确处理大页（`translate` 已支持叶子出现在任意级）；
- 验收：`map_huge` 后 `walk` 只走两级，翻译 `va + 0x1ff000` 仍正确。

### C. COW 引用计数模拟

- 验收：写之前共享计数为 2，写之后父子各自持有独立帧。

## 9. 常见问题

**Q：`free` 报"不在实验台持有列表中"？**
A：只有通过 `alloc` / `map ... auto` 分配给实验台的帧才能 `free`。页表内部帧由页表自己管理。

**Q：`map` 报地址未对齐？**
A：Sv39 的 4 KiB 页要求 VA、PA 都是 4096 的整数倍。

**Q：`reset` 之后映射没了，但帧数没降？**
A：`reset` 只回收页表帧；你用 `alloc` / `map auto` 拿到的数据帧仍在持有列表中，需要 `free`。

**Q：输出里的 PPN 和物理地址对不上？**
A：`PPN × 4096 = 物理地址`。例如 PPN `0x8_0001` 对应 `0x8000_1000`。

**Q：颜色乱码？**
A：加 `--no-color`，或把输出重定向到文件（程序会自动关闭颜色）。
